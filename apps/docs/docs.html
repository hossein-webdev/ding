مستندات

روی هر مثال دکمهٔ اجرا را بزنید تا توست واقعی را ببینید. متن ساده می‌خواهید؟ llms.txt

نصب

فایل استایلی برای ایمپورت کردن وجود ندارد: استایل‌ها از داخل جاوااسکریپت تزریق می‌شوند.

npm i @yusufceng1z/ding-react

از shadcn/ui استفاده می‌کنید؟ این دستور پکیج را نصب می‌کند و یک wrapper به نام ding-toaster.tsx هم اضافه می‌کند:

npx shadcn@latest add @ding/ding
npm i @yusufceng1z/ding-svelte
npm i @yusufceng1z/ding-vue
npm i @yusufceng1z/ding

راه‌اندازی

فقط یک بار، نزدیک ریشهٔ برنامه، Toaster را رندر کنید.

import { Toaster } from '@yusufceng1z/ding-react';

export default function App() {
  return (
    <>
      <Toaster position="top-center" theme="system" />
      {/* your app */}
    </>
  );
}
<script>
  import { Toaster } from '@yusufceng1z/ding-svelte';
</script>

<Toaster position="top-center" theme="system" />
<script setup>
import { Toaster } from '@yusufceng1z/ding-vue';
</script>

<template>
  <Toaster position="top-center" theme="system" />
  <!-- your app -->
</template>
import { mountToaster } from '@yusufceng1z/ding';

const unmount = mountToaster({ position: 'top-center' });

Nuxt

کامپوننت Toaster در رندر سرور چیزی تولید نمی‌کند و بعد از بارگذاری صفحه شروع به کار می‌کند، پس رندر سمت سرور مشکلی ندارد. آن را در app.vue قرار دهید و toast را از کد سمت کلاینت صدا بزنید، مثلاً در یک رویداد کلیک یا onMounted:

<!-- app.vue -->
<template>
  <Toaster position="top-center" theme="system" />
  <NuxtPage />
</template>

<script setup>
import { Toaster } from '@yusufceng1z/ding-vue';
</script>

Next.js

این پکیج با "use client" علامت‌گذاری شده است، پس Toaster را می‌توان مستقیم در app/layout.tsx گذاشت و این فایل همچنان یک server component باقی می‌ماند:

import { Toaster } from '@yusufceng1z/ding-react';

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en">
      <body>
        {children}
        <Toaster position="top-center" theme="system" />
      </body>
    </html>
  );
}

تابع toast را فقط از کامپوننت‌های کلاینتی صدا بزنید. در راهنمای Next.js دربارهٔ server actions هم توضیح داده شده است. اگر از Pages Router استفاده می‌کنید، <Toaster /> را در pages/_app.tsx رندر کنید.

نمایش توست

تابع toast را از همان پکیج ایمپورت کنید و هر جا که خواستید صدایش بزنید. هر فراخوانی شناسهٔ توست را برمی‌گرداند. toast.loading(title) هم همین‌طور کار می‌کند و تا وقتی آن را به‌روزرسانی نکنید یا نبندید، روی صفحه می‌ماند.

import { toast } from '@yusufceng1z/ding-react@yusufceng1z/ding-svelte@yusufceng1z/ding-vue@yusufceng1z/ding';

toast.success('Saved');
toast.error('Payment failed', { description: 'Card declined' });
toast.warning('Storage almost full');
toast.info('New version available');

هر زمان فقط یک توست دیده می‌شود. فراخوانی جدید به‌جای روی هم چیدن توست دوم، همان توستِ روی صفحه را درجا تغییر شکل می‌دهد. اگر همان توست تکرار شود، شمارنده‌ای (×۲) به آن اضافه می‌شود.

به‌روزرسانی درجا

یک promise را به توست بدهید تا همان یک توست از حالت «در حال بارگذاری» به نتیجه برسد:

toast.promise(save(), {
  loading: 'Saving…',
  success: 'Saved',
  error: (err) => `Could not save: ${err.message}`,
});

یا برای نمایش پیشرفت و کارهای طولانی دیگر، به‌روزرسانی را دستی انجام دهید:

const id = toast.loading('Uploading photo…', { progress: 0 });
toast.update(id, { progress: 0.6 });
toast.update(id, { type: 'success', title: 'Photo uploaded', progress: null });

فقط جدیدترین فراخواننده می‌تواند توستِ مشترک را به‌روزرسانی کند، پس درخواست کندی که دیر تمام شود نمی‌تواند پیام جدیدتر را بازنویسی کند.

دکمه‌های اقدام

تابع onClick می‌تواند یک شیء به‌روزرسانی (patch) برگرداند. در این صورت توست بسته نمی‌شود و درجا تغییر شکل می‌دهد. شیء برگشتی دکمه‌ها را حذف می‌کند، مگر اینکه دوباره در آن به دکمه‌ها اشاره کنید.

toast.success('Message deleted', {
  action: {
    label: 'Undo',
    onClick: () => {
      restore();
      return { type: 'info', title: 'Restored' };
    },
  },
});

گزینه‌ها

description
خط دوم متن.
action
{ label, onClick }. دکمهٔ اصلی.
secondary
{ label, onClick }. دکمه‌ای کم‌رنگ‌تر در کنار دکمهٔ اقدام.
image
نشانی (URL) آواتار یا تصویر بندانگشتی. جایگزین آیکون وضعیت می‌شود.
meta
متن کوچک انتهایی، مثل «الان» یا «⌘V».
progress
عددی از ۰ تا ۱. نواری باریک در پایین توست نشان می‌دهد.
duration
مدت نمایش به میلی‌ثانیه تا بسته شدن توست. مقدار 0 آن را تا زمانی که بسته نشود نگه می‌دارد. پیش‌فرض: 5000.
id
یک شناسه را دوباره استفاده کنید تا فراخوانی‌های تکراری از یک نقطه، یک فراخواننده حساب شوند.

توست‌های خطا و بارگذاری و توست‌هایی که دکمه دارند ماندگارند و تا وقتی بسته نشوند روی صفحه می‌مانند، تا کسی چیزی را که باید رویش اقدام کند از دست ندهد. قرار گرفتن ماوس روی توست و فوکوس صفحه‌کلید، تایمر را متوقف می‌کنند.

پیکربندی

toast.configure({
  position: 'bottom-right', // top-left, top-center, top-right, bottom-left, bottom-center, bottom-right
  theme: 'dark',            // system, light, dark
  labels: { dismiss: 'Fermer la notification' }, // screen reader names, English by default
  sound: true,
  volume: 0.5,
});

toast.dismiss(id);  // one toast
toast.dismiss();    // all

جایگاه، پوسته و برچسب‌ها را می‌توان به‌صورت prop روی Toaster هم تنظیم کرد. توست جهت خواندن صفحه را دنبال می‌کند، پس در صفحه‌های راست‌به‌چپ به‌صورت خودکار قرینه می‌شود.

گزینهٔ labels نام‌هایی را تعیین می‌کند که صفحه‌خوان‌ها برای ناحیهٔ اعلان‌ها (region) و دکمهٔ بستن (dismiss) می‌خوانند. کلیدهایی که نیاورید مقدار پیش‌فرض انگلیسی خود را نگه می‌دارند، پس صفحه‌ای که انگلیسی نیست فقط باید همان‌هایی را ترجمه کند که به کار می‌برد.

سیاست امنیت محتوا (CSP)

استایل‌ها به‌صورت یک عنصر <style> تزریق می‌شوند. اگر CSP شما استایل‌های درون‌خطی را مسدود می‌کند (یعنی style-src بدون 'unsafe-inline')، مقدار nonce صفحه را به آن بدهید. مقدارهای مخصوص هر توست از طریق DOM تنظیم می‌شوند که CSP اجازه‌اش را می‌دهد، پس تنها چیزی که به nonce نیاز دارد خودِ شیت استایل است.

<Toaster nonce={nonce} />
<Toaster nonce={nonce} />
<Toaster :nonce="nonce" />
mountToaster({ nonce });

در Next.js، مقدار nonce را که proxy شما تنظیم کرده است با (await headers()).get('x-nonce') در یک server component بخوانید و آن را به پایین بدهید.

استایل‌دهی

رنگ‌ها و شعاع گوشه‌ها متغیرهای CSS هستند. آن‌ها را در فایل استایل خودتان تنظیم کنید تا روی همهٔ توست‌ها اعمال شوند، با هر فریم‌ورکی که استفاده می‌کنید.

.tst-viewport {
  --tst-radius: 8px;
  --tst-bg: #1e3a8a;
  --tst-fg: #fff;
  --tst-success: #16a34a;
}
متغیرپیش‌فرضکاربرد
--tst-radius22pxشعاع گوشه. مقدار پیش‌فرض شکل کپسول می‌سازد
--tst-bglight-dark(#fff, #0c0c0d)پس‌زمینه
--tst-fglight-dark(#0f0f13, #fafafa)متن
--tst-successlight-dark(#12a36b, #4ade80)آیکون موفقیت
--tst-errorlight-dark(#e5484d, #f87171)آیکون خطا
--tst-warninglight-dark(#c77d00, #fbbf24)آیکون هشدار
--tst-infolight-dark(#2f7de1, #60a5fa)آیکون اطلاع

مقدارهای پیش‌فرض از طریق light-dark() پوسته را دنبال می‌کنند. اگر فقط یک مقدار بدهید، برای هر دو پوسته اعمال می‌شود. برای اینکه این دو از هم جدا بمانند، خودتان بنویسید: --tst-bg: light-dark(#fff, #111).

توست‌های پر (filled)

هر توست سه متغیر --fill (سطح)، --on (متن، دکمه‌ها، دکمهٔ بستن، حلقهٔ فوکوس) و --c (رنگ آیکون) دارد؛ مقدارشان را عوض کنید تا کل توست با رنگ وضعیتش پر شود.

.tst-viewport .tst[data-type=error] { --fill: #e5484d; --on: #fff; --c: #fff; }

یک توست، یک استایل

className را به فراخوانی بدهید و آن را به‌صورت .tst.your-class استایل کنید. toast.update(id, { className: null }) آن را برمی‌دارد.

toast.success('ذخیره شد', { className: 'big' });

فنرها

سه حرکت را دوباره تنظیم کنید؛ هرکدام { stiffness, damping } می‌گیرد. هرکدام را ندهید، مقدار پیش‌فرضش می‌ماند (ورود ۳۲۰/۲۶، تاخوردن ۳۴۰/۲۷، چیدمان ۴۰۰/۳۶). روی توست‌هایی که بعد از آن نشان داده می‌شوند اعمال می‌شود.

toast.configure({ springs: { enter: { stiffness: 220, damping: 14 } } });

آیکون‌ها

آیکون یک وضعیت را با مسیرهای SVG خودتان روی شبکهٔ ۲۴×۲۴ عوض کنید (به‌صورت stroke). مسیر اول همیشه حلقهٔ بیرونی است. برای warning و info سه مسیر نگه دارید، چون انیمیشنشان مسیر دوم و سوم را هدف می‌گیرد.

toast.configure({ icons: { success: ['M12 3a9 9 0 1 0 0 18a9 9 0 1 0 0-18', 'M8 12l3 3 5-6'] } });

صدا

به‌طور پیش‌فرض خاموش است. آن را روشن کنید تا هر وضعیت نوای ملایم خودش را داشته باشد: موفق صعودی است، خطا نزولی، هشدار دو ضربهٔ کوتاه دارد و اطلاع فقط یک نت است. حالت بارگذاری بی‌صداست و به‌روزرسانی‌های پیشرفت هرگز صدایی ندارند.

toast.configure({ sound: true, volume: 0.5 });

مرورگرها تا قبل از کلیک یا فشردن یک کلید، پخش صدا را قفل نگه می‌دارند، پس اولین صدا باید بعد از یکی از این دو بیاید. برای استفاده از صدای خودتان یا یک کتابخانهٔ صدا، یک تابع بدهید. این تابع یکی از مقدارهای success، error، warning، info یا loading را دریافت می‌کند، یک بار برای هر توست جدید و یک بار برای هر تغییر وضعیت.

toast.configure({ sound: (type) => mySounds.play(type) });

دسترس‌پذیری

  • پیام‌ها از طریق ناحیه‌های زندهٔ دائمی (live region) اعلام می‌شوند: خطاها با اولویت بالا (assertive) و بقیه با اولویت عادی (polite).
  • با Esc توست بسته می‌شود. با Alt + T فوکوس به توست می‌رود.
  • از تنظیم «کاهش حرکت» (prefers-reduced-motion) پیروی می‌کند.
  • دکمه‌ها تا وقتی توست کامل باز نشده باشد، در ترتیب Tab قرار نمی‌گیرند.
