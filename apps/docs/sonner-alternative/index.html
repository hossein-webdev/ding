جایگزینی برای Sonner که هر بار یک توست نشان می‌دهد

Sonner کتابخانهٔ خوبی است و توست‌ها را روی هم می‌چیند. Ding انتخاب دیگری کرده است: یک توست روی صفحه، و پیام جدید توست فعلی را به توست جدید تبدیل می‌کند. اینکه کدام را بخواهید به برنامه‌تان بستگی دارد.

امتحان کنید:

چرا هر بار فقط یک توست ساختم

در برنامه‌هایی که رویشان کار می‌کنم، پشت‌سرهم آمدن چند رویداد (ذخیره، بعد همگام‌سازی، بعد یک درخواست ناموفق) پشته‌ای می‌ساخت که صفحه را می‌پوشاند و خواندنش از یک پیام تکی سخت‌تر بود. می‌خواستم آخرین پیام برنده شود و انتقالی دیده شود تا کاربر بفهمد پیام عوض شده است.

چه زمانی Ding را انتخاب کنید

هر بار یک پیام می‌خواهید. همان توست را در حالت‌های بارگذاری، موفقیت و بازگردانی به‌روزرسانی می‌کنید. بدون وابستگی و بدون ایمپورت CSS می‌خواهید. یا علاوه بر React از Svelte 5 یا جاوااسکریپت ساده هم استفاده می‌کنید.

چه زمانی Sonner را انتخاب کنید

چند توست را هم‌زمان لازم دارید، یا اکوسیستم بزرگ‌تر و سابقهٔ بیشتری می‌خواهید. Ding توست‌ها را روی هم نمی‌چیند و این قرار نیست تغییر کند.

تعویض کتابخانه

فراخوانی‌ها آشنا به نظر می‌رسند. یک Toaster رندر کنید، سپس:

import { toast } from '@yusufceng1z/ding-react';

      toast.success('Saved');
      toast.promise(save(), { loading: 'Saving…', success: 'Saved', error: 'Failed' });

پیش از تعویض، گزینه‌هایی را که استفاده می‌کنید با مستندات مقایسه کنید، چون همهٔ گزینه‌ها وجود ندارند. جزئیات راه‌اندازی در اعلان‌های توست در React است. اگر از Svelte استفاده می‌کنید، جایگزین svelte-sonner را ببینید.

کد Ding در GitHub به‌صورت متن‌باز در دسترس است. یک ستاره ساده‌ترین راه برای گفتن این است که به کارتان آمده.

پروژهٔ Ding را Yusuf Cengiz ساخته است. دارای مجوز MIT، کد منبع در GitHub.
